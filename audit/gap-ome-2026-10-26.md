# Shared OME metadata export corrections — 2026-10-26

Status: implemented and focused validation passed. These are shared model/export corrections, separate from the Leica source-reader findings in `gap-leica-2026-10-26.md`.

## Corrected behavior

- OME 2016-06 Instrument children now follow Microscope, light source, Detector, Objective, FilterSet, Filter, Dichroic order. Image children follow AcquisitionDate, Description, InstrumentRef, ObjectiveSettings, ImagingEnvironment, StageLabel, Pixels, ROIRef, AnnotationRef order. Channel settings precede FilterSetRef and LightPath. StructuredAnnotations precedes ROI.
- Filter cut-in/cut-out values serialize in a TransmittanceRange child. Parsing accepts this schema representation and the older attribute representation.
- Self-closing Channel and FilterSet elements cannot inherit later siblings' child references. Shared scoped-block extraction also handles self-closing elements; Instrument parsing uses the scoped block.
- The existing plate/screen/well/well-sample graph now serializes and parses, including custom IDs, sample coordinates and image references. References resolve arbitrary source Image IDs against the complete image list and export the corresponding generated Image IDs. Unset plate Rows/Columns are omitted instead of exporting invalid zero PositiveInt values.
- Channel DetectorSettings, optical acquisition attributes, LightPath references and imaging temperature now survive XML parsing and export. Bit pixels infer one significant bit when the source omits SignificantBits.
- Modulo metadata now exports as image-linked XMLAnnotations, including labels, instead of invalid direct Pixels children.
- Each image retains its own core pixel description through `OmePixels`; this is populated by `populate_pixels` and therefore by the existing LEI and LMS/XLEF constructors via `from_image_metadata`.
- `to_ome_xml` explicitly exports a metadata-only document because the model contains no pixel-storage mapping. It emits the required MetadataOnly choice before Plane children. The three TIFF-writer entry points replace the first image's MetadataOnly marker with TiffData, where the writer knows that consecutive TIFF IFDs hold that image's pixels. Additional images retain MetadataOnly rather than claiming an invented overlapping IFD mapping.
- StageLabel always exports the schema-required Name attribute (empty when the optional model name is unset).

`OmeExperiment` and `OmeDataset` are currently unattached type declarations, not fields in OmeMetadata; this change does not add unrelated graph classes to the public store.
