# Thumbnail adapter completion — 2026-10-26

Status: implemented and focused checks passed. This closes the inherited thumbnail gaps in TissueFAXS, Fake and CZI; Pyramid TIFF retains its specialized thumbnail-IFD behavior.

## Source and implementation

The primary source is local Bio-Formats revision `d54bf462e3`:

- `components/formats-api/src/loci/formats/FormatReader.java:815–850`: default thumbnail dimensions preserve aspect ratio and use a maximum dimension of 128; images smaller than 128 in both axes retain their size.
- `components/formats-api/src/loci/formats/FormatTools.java:1288–1349`: open the plane, construct an AWT image with floating-point normalization enabled, make signed data unsigned, scale, and concatenate pixel bytes in the reader's original channel arrangement and endianness.
- `components/formats-bsd/src/loci/formats/gui/AWTImageTools.java`: `openImage`, `makeUnsigned`, `scale`, `makeBuffered`, `getPixelBytes` and image/color-model construction.
- `Index16ColorModel`, `SignedColorModel`, `UnsignedIntColorModel` and `TwoChannelColorSpace` in the same directory supply the nonstandard model behavior.

`src/common/thumbnail.rs` adapts those Java library calls to Rust. It resamples the entire source plane rather than center-cropping ordinary images. Explicit thumbnail dimensions remain available for Fake's `thumbSizeX`/`thumbSizeY` overrides. It preserves active series/resolution and checks initialization and plane range.

AWT's area filter averages rendered 8-bit sRGB values using float accumulators and integer overlap weights. Therefore a scaled 16-bit thumbnail is quantized through 8-bit rendering; directly averaging original 16-bit samples would differ. Float32/Float64 inputs use `DataTools.normalizeFloats`/`normalizeDoubles`, including their positive-subnormal initial maximum and canonical serialized NaNs. Gray float destinations use the 256-entry ICC conversion tables generated by the retained Java oracle. RGBA thumbnails additionally reproduce Java2D's premultiplied intermediate and rounded 24-bit reciprocal in `div8table`.

`src/common/thumbnail_indexed.rs` implements the AWT indexed-byte destination conversion: the ordered 8×8 component dithers, the 5-bit inverse color cube, native palette-order and frontier tie behavior, primary-color optimization, and the grayscale-palette inverse map. Its derivation and generator are retained in `tests/fixtures/thumbnail/INDEXED.md` and `PaletteGrid.java`. Indexed uint16 destinations intentionally store the averaged red8 as a uint16 value; Java's `Index16ColorModel.getDataElements` ignores its palette when writing that destination.

The TissueFAXS thumbnail method now calls this adapter. The pyramid worker also wired Fake and CZI and corrected Fake's missing deterministic Java LUT/inverse lookup behavior. Specialized Pyramid TIFF thumbnail IFDs remain handled separately by its reader.

## Source behavior and validation limits

These are Java behavior, not deferred implementations:

- Scaled scalar int32/uint32 thumbnails are zero-valued: `UnsignedIntColorModel` delegates to an integer `ComponentColorModel` whose 32-bit component mask wraps to zero. Java synthetic inputs spanning the full uint32 range confirmed this.
- Java rejects scaled multichannel floating-point and multichannel int32/uint32 model/raster combinations. Signed RGB int8 is rejected while constructing its AWT image, including before any resizing. The adapter returns a format error for these source-rejected combinations.
- Java's negative signed-plane-size overflow branch reads a centered crop four times the thumbnail dimensions, then still constructs an image using the original full dimensions. The adapter attempts that same crop and reports the invalid full raster instead of allocating a multi-gigabyte substitute image.

The checks establish synthetic parity for the exercised models and dimensions. They do not constitute a proprietary TissueFAXS corpus comparison, an exhaustive test of huge images, or a guarantee that every JDK/ICC rendering implementation chooses identical floating conversion tables. Runtime Rust code needs no JVM or native AWT dependency.
