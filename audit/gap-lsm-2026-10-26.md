# Zeiss LSM implementation closure — 2026-10-26

Reference: `java-bioformats/components/formats-gpl/src/loci/formats/in/ZeissLSMReader.java`
at `d54bf462e3`. Implementation: `src/formats/gpl/zeiss_lsm.rs`.

## Closed implementation gaps

- MDB entrypoints use the existing pure-Rust MDB service to read
  `Recordings.SampleData`, normalize Windows/Unix paths to local basenames,
  preserve database row order, and apply Java's missing-reference sibling
  fallback and competing-database exclusion behavior. Direct `.lsm` entrypoints
  stay single-file, as Java `initFile` does.
- Every referenced LSM has its own TIFF reader, calibration, scan information,
  channel colors/names, timestamp/position metadata and logical plane offsets.
  Series selection delegates pixel and LUT reads to the corresponding file;
  metadata from one source is not reused for another.
- OME output includes every logical series, shares one instrument per source LSM,
  remaps optical-component IDs/references, assigns unique ROI IDs, and projects
  experimenter usernames. Multi-position names follow Java's source/series
  count condition. Opening an MDB with no usable LSM fails explicitly.
- The Java overlay types now project labels, lines, rectangles, three/four-point
  ellipses, circles, three-point circles, open/closed polylines and Bezier control
  polygons, and angles. Font size, stroke width and ellipse transforms are
  preserved through the shared typed `OmeShape::Styled` model. Source-unsupported
  scale bars, arrows and palettes remain skipped as Java does. Truncated blocks
  are bounded before reads/allocations.
- Event time/type/description lists and all supported application-tag value types
  (ASCII, long, rational, date, Boolean) are retained in original metadata.
  Existing SIM-specific black-channel color fallback remains in place.
- Metadata levels suppress overlays and minimum-level rich OME projection while
  retaining pixels/core metadata and instrument links.
- Rich scan-information fields now populate objective iris, normalized
  correction/immersion enums, laser type/medium, detector amplification gain and
  zoom, including Java's numeric zero and missing-value behavior. Source-absent
  Objective.Model, Laser.Power and DetectorSettings.Gain/Binning overprojection
  was removed. Detector references require the source channel-name guard.
  Explicit empty channel names remain explicit empty names.

Two surprising Java behaviors are retained for source parity: ellipse rotation
uses the degree-valued angle passed into `sin`/`cos`; emission-filter references
use the instrument/source index as the destination image index, even in
multi-position datasets. Regression tests cover both.

## Stale audit claims resolved

- `OffsetChannelWavelength` is read and retained by Java but **never consumed**.
  Implementing a separate table-to-OME wavelength projection would add behavior
  absent from the reference; this is not a remaining implementation gap.
- MDB grouping, ROI overlay projection, event/application values and OME
  experimenter username were genuine implementation gaps and are implemented
  above. They should no longer appear as open implementation work.
- The historical real-fixture warnings remain evidence limits only, not reasons
  to leave these paths unimplemented.
